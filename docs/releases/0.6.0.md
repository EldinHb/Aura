## What's new

### Remote access, and an Android app

Work with your sessions from your phone. Remote access is **off by default**; you
turn it on, and only devices you pair can connect.

- **Opt-in listener.** `aurad` can serve a second WebSocket, with TLS, next to the
  local one. Turn it on in Settings → Remote access or with `aura remote on` (default
  `0.0.0.0:7443`; `--bind`, `--port` and `--name` change it). Changes apply without
  restarting the daemon.
- **Pinned certificate.** Aura makes a self-signed certificate the first time you turn
  remote access on. The phone pins its SHA-256 fingerprint when it pairs and refuses
  any other certificate afterwards, so nobody in between can listen in.
- **QR pairing.** Pair a device with a QR code (Settings → Remote access → Pair a
  device…, or `aura remote pair`), an `aura://pair` link or the details by hand. The
  one-time code works once and lasts 5 minutes; failed attempts are rate limited.
- **Per-device tokens, and revoking.** A paired device gets a token of its own. See
  paired devices and when they were last seen, and revoke one at any time
  (`aura remote devices`, `aura remote revoke <device-id>`); it is disconnected at once.
- **A method allowlist.** Remote devices can list sessions, read transcripts live, send
  messages, answer approvals and questions, interrupt or stop, and start a session in a
  project you already use. They cannot change settings, browse files, manage mods,
  delete sessions, use terminals or change remote access itself.
- **Agents cannot enable it.** `aura remote on` and `pair` ask you to confirm at a
  terminal and refuse to run inside an Aura session, so an agent cannot open your
  machine to the network.
- **SSH tunnel instead.** Bind the listener to this machine only
  (`aura remote on --bind 127.0.0.1`), tunnel to it with
  `ssh -L 7443:127.0.0.1:7443 you@your-mac`, and connect to `wss://127.0.0.1:7443/`
  with the same fingerprint.

The protocol, the threat model and the exact methods remote clients may call are in
[`docs/design/remote.md`](../design/remote.md).

### Aura for Android

A native app (Kotlin, Jetpack Compose, Material 3) for Android 8.0 and later.

- A **Waiting on you** inbox across all your servers: approvals, agents' questions and
  feature owners' questions, answered from the phone.
- Your sessions and their transcripts, live; send messages, interrupt or stop an
  agent, and start new sessions in your projects.
- **Material You**: dynamic colour on Android 12 and later, light and dark following
  the system.
- **Several servers**: pair more than one computer and switch between them.
- The device token is kept encrypted with a key in the Android Keystore; it is not
  backed up or moved to another phone.

**Install it.** Download `Aura-0.6.0-android.apk` below, copy it to the phone and open
it (Android asks to allow installing from that source), or use
`adb install -r Aura-0.6.0-android.apk`. If the release was built without Aura's
release key the APK is signed with a debug key: it installs the same, but a later
release signed with the release key cannot update it: remove the app first.

**Pair it.** On your computer run `aura remote on` and `aura remote pair` (or use
Settings → Remote access). In the app tap **Add server** and scan the QR code, paste
the link or enter the details, check that the fingerprint matches the one Aura shows,
and tap **Pair**. The phone must reach the computer: the same Wi-Fi, a VPN such as
Tailscale, or an SSH tunnel.

### The `aura remote` command

```bash
aura remote status
aura remote on [--port 8443] [--bind 192.168.1.10] [--name "Studio Mac"]
aura remote pair                  # one-time code and aura:// link, valid 5 minutes
aura remote devices
aura remote revoke <device-id>
aura remote off
```

Everything lives in `~/.aura/remote/`, readable only by you.
